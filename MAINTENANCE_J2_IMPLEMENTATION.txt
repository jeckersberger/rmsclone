================================================================================
                        DATABASE SCHEMA
================================================================================

NEW TABLES (5):

1. maintenance_schedules
   ├─ Purpose: Maintenance plan templates (recurring)
   ├─ Key Fields:
   │  ├─ asset_type_id | asset_id (which to maintain)
   │  ├─ interval_type (days|months|uses|hours)
   │  ├─ interval_value (quantity)
   │  ├─ next_due_at (automated calculation)
   │  └─ is_active (enable/disable)
   └─ Relationships: assetTypes, assets, instances

2. maintenance_jobs
   ├─ Purpose: Individual maintenance tasks
   ├─ Key Fields:
   │  ├─ asset_id (what to maintain)
   │  ├─ status (scheduled|in_progress|completed|cancelled)
   │  ├─ priority (low|medium|high|critical)
   │  ├─ estimated_cost, actual_cost (tracking)
   │  ├─ assigned_to, completed_by (users)
   │  └─ created_at, started_at, completed_at (timestamps)
   └─ Relationships: schedule, assets, users, instances

3. maintenance_job_photos
   ├─ Purpose: Visual documentation of work
   ├─ Key Fields:
   │  ├─ file_path (S3 or local)
   │  ├─ description (optional notes)
   │  └─ uploaded_by (user reference)
   └─ Relationships: jobs, users

4. maintenance_checklists
   ├─ Purpose: Template for standardized checklists
   ├─ Key Fields:
   │  ├─ name (checklist title)
   │  ├─ asset_type_id (optional, type-specific)
   │  └─ items (JSON array of checklist items)
   └─ Relationships: assetTypes, instances

5. maintenance_checklist_results
   ├─ Purpose: Completed checklists for jobs
   ├─ Key Fields:
   │  ├─ results (JSON with completion status)
   │  ├─ completed_by, completed_at (tracking)
   │  └─ notes per item (optional)
   └─ Relationships: jobs, checklists, users

RELATIONSHIPS:
- One asset can have many jobs
- One schedule can create many jobs
- One job can have many photos and checklist results
- One checklist template used by many jobs
- All linked to instances (multi-tenant)

INDEXES: 17 total (optimized for key queries)
- Schedule due date lookups
- Job status filtering
- Asset history retrieval
- Completion date analysis

================================================================================
                        WORKFLOW EXAMPLES
================================================================================

WORKFLOW 1: AUTOMATED PREVENTIVE MAINTENANCE

Step 1: Setup (Admin)
  - Create Schedule: "Ölwechsel"
  - Asset Type: "Motor"
  - Interval: 6 months

Step 2: Automation (CRON Daily)
  - System calculates next_due_at = now + 6 months
  - CRON triggers daily
  - When next_due_at <= now and no open job exists
    → Creates new Job automatically

Step 3: Execution (Technician)
  - Opens Dashboard
  - Sees new job in "Offene Aufträge"
  - Clicks job, assigns to self
  - Changes status → "in_progress"
  - Performs checklist items
  - Uploads before/after photos
  - Marks "completed"
  - Enters actual_cost

Step 4: Analytics (Manager)
  - Views "Kostenübersicht"
  - Sees estimated vs actual cost
  - Identifies budget variances
  - Optimizes future estimates

WORKFLOW 2: AD-HOC REPAIR

Step 1: Report (Technician)
  - Notices equipment problem
  - Creates new Job manually: "Hydraulik-Druck niedrig"
  - Sets priority: "critical"

Step 2: Assignment (Supervisor)
  - Reviews open jobs
  - Assigns to experienced technician
  - Sets estimated_cost

Step 3: Execution (Technician)
  - Works on job
  - Adds detailed notes
  - Uploads problem/solution photos
  - If recurring: Creates new Schedule

Step 4: Prevention (System)
  - If schedule created: Future occurrences handled automatically

WORKFLOW 3: COMPLIANCE AUDIT

Step 1: Setup (Admin)
  - Create Checklist: "Jährliche TÜV-Inspektion"
  - Items: [Bremstest, Lichter, Reifen, Ausrichtung]
  - Create Schedule: "TÜV", Asset Type: "Vehicle", Interval: 12 months

Step 2: Job Creation (CRON)
  - When due date reached, job created automatically

Step 3: Execution (Technician)
  - Opens job
  - Selects Checklist
  - Completes each item
  - Adds notes per item
  - Saves results

Step 4: Audit (Manager)
  - Verifies completion
  - Generates compliance report
  - Archives for regulatory requirements
